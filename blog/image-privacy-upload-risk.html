选在线图片压缩工具时，大多数人只看"压得够不够小"。但如果你处理的是身份证、合同、 内部资料、带人脸的私人照片，有一个比压缩率重要得多的因素：你的图片去了哪里。

一、绝大多数在线工具会拿到你的图片

主流在线压缩工具的工作方式是：

  1. 你把图片上传到它的服务器
  2. 服务器上执行压缩
  3. 压缩结果下载回你的浏览器

注意第一步——图片完整地落在了对方的服务器上。这是它的架构决定的，不是"态度问题"。

二、"我们承诺几小时后删除"意味着什么

很多工具会写"文件24小时内自动删除，请放心"。这句话在技术上可能是真的，但你要知道：

  • 无法验证。你没法检查对方硬盘上还有没有你的文件，也没有第三方审计。
  • "删除"的定义模糊。备份、日志、缓存、云存储的多副本机制， 都可能让文件在"删除"后继续存在一段时间。
  • 传输过程本身有暴露窗口。即使 HTTPS 加密， 图片在对方服务器上解密后的那一小段时间是完全明文可读的。
  • 泄露风险是累积的。这类服务会集中存储海量用户图片， 一旦被入侵，影响面极大——这类事故在行业里并不罕见。

换句话说：你付出的是信任，得到的是一句无法核实的承诺。

三、纯浏览器本地处理意味着什么

另一类工具的架构完全不同：压缩在你的浏览器里完成。

现代浏览器有两个能力让这件事成为可能：

  • Canvas API：能在本地解码、重绘、重新编码图片
  • Blob / toBlob()：能生成新的图片文件供下载

整个流程不需要服务器参与。所以这类工具可以做到：

  • 图片从不发起网络上传请求
  • 断网状态下也能正常使用
  • 不产生任何存储，因为根本没有地方存

这不是"服务商更有良心"，而是架构上没有那个能力——这个区别很重要： 承诺可以被违背，架构不能被违背。

四、怎么自己验证（30 秒）

不用相信任何宣传，你自己就能查：

  1. 在工具页面按 F12 打开开发者工具
  2. 切到 Network（网络） 面板，勾选 Preserve log
  3. 清空记录，然后处理一张图片
  4. 观察请求列表

判断标准：

  • 如果出现 POST 到某个服务器的、体积很大的请求 → 图片被上传了
  • 如果只有页面本身的静态资源（html/css/js）→ 图片留在本地，没有上传

这个方法是无法作弊的，比任何文字承诺都可靠。

进阶验证：断网测试

更直观的做法：打开工具页面并完成首次加载，然后把网络断开（关 Wi-Fi / 拔网线）， 再上传一张图片处理。

  • 能正常压缩并下载 → 说明计算全在本地 ✅
  • 报错或卡住 → 说明依赖服务器 ❌

五、还有两个容易忽略的隐私点

1. EXIF 里的位置信息

手机拍的照片里通常嵌着 EXIF 元数据，其中包括 GPS 经纬度。 把这样的原图直接发出去，等于公开了你的拍摄地点。

好消息是：用 Canvas 重绘会丢掉 EXIF。 所以本地压缩类工具在压缩的同时，顺带帮你清掉了位置隐私。 （但如果你是"只重命名、不改内容"地传原图，位置信息就还在。）

2. 文件名也是信息

身份证_张三_正面.jpg 这种文件名本身就泄露信息。 下载前顺手改个名，成本几乎为零。

六、什么场景应该坚持用本地工具

图片内容建议
身份证 / 护照 / 驾照 / 银行卡✅ 必须本地处理
合同 / 病历 / 内部文档截图✅ 必须本地处理
含人脸的家庭照 / 儿童照片✅ 建议本地处理
带门牌号、车牌、公司内部环境的照片✅ 建议本地处理
未公开的产品图 / 设计稿✅ 必须本地处理
公开素材图、表情包⚠️ 上传类工具也可接受

判断规则很简单：如果这张图泄露出去你会不舒服，就不要上传到任何服务器。 本地工具已经足够好用，没有理由为了省几秒钟去承担这个风险。

七、试一下

我们的图片压缩工具就是纯本地架构： 没有后端服务器，图片不上传，可以直接按上面的方法验证。 处理敏感图片时，建议先用断网测试确认一遍——养成习惯比记住结论更有用。
